# 图标管理与多 Steam 账号

当前规则说明。历史验收数据见 [2026-09-08 联动记录](archive/2026-09-08-integration.md)。

## 图标

在后台“技能”或“社交链接”的编辑页，可以选择“浅色背景图标 / 通用”和“深色背景图标（可选）”。浅色、深色指的是图标所在区域的背景色：浅色背景一般配深色图案，深色背景配浅色图案。选择器和候选图分别用固定的白底和黑底预览，不受后台主题影响。页脚背景与页面相反时，博客按页脚的实际背景选图。

图标可以复用媒体库里的图片，也可以在弹窗里上传。上传成功后选中素材，再保存业务记录。

- 支持 PNG、JPEG、WebP 和 SVG。SVG 在浏览器里先转成 PNG，后端只接收像素图并存为无损 WebP，不托管原始 SVG。转换失败的 SVG 请先导出为 PNG。
- 图标最长边不超过 512 像素，上传上限 10 MiB。
- 没设深色版本时复用通用图标；只设了深色版本时两个主题都用它。两张都清空时，后台和社交链接显示默认图形，技能球只绘制有图片的技能，名称仍保留在无障碍列表里。
- 图标被技能或社交链接引用时，删除媒体返回 409。

接口字段：请求用 `iconMediaId`、`darkIconMediaId`，响应带 `icon`、`darkIcon` 媒体对象。`iconKey` 只为兼容旧客户端保留，后台新建的记录固定写 `custom`。

图标的二进制存在数据库里，通过后端 `/media/:id/content` 读取。把媒体库里已有的图片选作图标时，后端会自动把它迁入数据库；也可以在后端目录用 `pnpm migrate:icons -- --check` 检查、`pnpm migrate:icons` 批量迁移。

## 多 Steam 账号

在后端被忽略的 `.env` 里配置 `STEAM_ACCOUNTS`。下面只是结构示例，占位值必须替换：

```dotenv
STEAM_SYNC_ENABLED=true
STEAM_SYNC_INTERVAL_SECONDS=300
STEAM_ACCOUNTS='[{"name":"vo1d","steamId":"<17位账号标识>","apiKey":"<该账号密钥>"},{"name":"vo2d","steamId":"<17位账号标识>","apiKey":"<该账号密钥>"}]'
```

`STEAM_ACCOUNTS` 非空时优先于旧的 `STEAM_ID` / `STEAM_API_KEY`；为空时沿用旧的单账号配置。支持 1–10 个不同的 SteamID64，重复账号会被拒绝。密钥只存在后端环境里，不进入浏览器、接口响应或文档。

改完配置后，在后端目录执行 `docker compose --profile app up -d`（代码有更新时加 `--build`）；本机直接运行后端则重启 `pnpm start:dev`。后台的 Steam 页面分别显示各账号的游戏数、最近成功时间、错误和冷却状态。

## 同一游戏的时长怎么合计

- 博客里一款游戏只关联一个 `steamAppId`。快照按“账号 + App ID”保存，公开响应按 App ID 合并。
- 把所有可用账号的 `playtimeMinutes` 相加，再取 `floor(总分钟 / 60)` 作为 `playtimeHours`。例如 31 分钟 + 31 分钟 = 1 小时。
- 自定义时长（接口字段 `manualPlaytimeHours`）大于 0 时覆盖 Steam 时长，填 0 则使用 Steam；没有快照且自定义为 0 时显示 0。两者不相加。
- `accountBreakdown` 返回各账号的分钟数和快照状态，公开响应不暴露 SteamID64。近两周分钟数只要有一个账号未知，合计就为空；最后游玩时间取最新值。
- 每个账号独立请求、冷却和重试。网络失败时保留上次的快照并标记 `stale`，其他账号照常更新。
- 已关联的游戏：账号变为私密或失去权限后，继续使用它最近一次成功的快照，并标记 `stale` / `incomplete`。从未成功同步的账号、已从配置移除的账号、确认不再拥有的游戏不计入。
- 新建关联和后台可选的游戏库只使用当前可见的快照。
- 评分、评论、喜爱等级、封面和顺序不会被同步覆盖；Steam 里的新游戏也不会自动变成博客条目。

技能球和游戏封面取色需要读取图片像素，图片服务必须允许博客来源跨域读取。

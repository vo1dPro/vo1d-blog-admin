# 图标管理与多 Steam 账号

更新日期：2026-09-07。启动端口仍是博客 5173、后台 5174、后端 3100。

## 图标如何修改

在后台“技能”或“社交链接”编辑页，选择“浅色背景图标 / 通用”和“深色背景图标（可选）”。浅色、深色指实际展示区域的背景颜色：浅色背景一般配深色图案，深色背景一般配浅色图案。选择器和媒体候选图分别用固定白底／黑底预览，不受后台主题影响。页脚与页面背景相反时，博客按页脚实际背景选图。可以复用媒体库图片，也可以在弹窗中上传新文件。上传成功后选择素材，再保存业务记录。

支持 PNG、JPEG、WebP，以及 SVG（Scalable Vector Graphics，可缩放矢量图形）。SVG 在浏览器以图片方式转换为 PNG，后端校验像素图片并保存为无损 WebP，不托管可执行的原始 SVG。无法转换的 SVG 可先导出 PNG。图标用途 `ICON` 输出最长边不超过 512 像素，上传文件上限为 10 MiB。

深色版本未设置时复用通用图标。只设置深色版本时两个主题都使用它。两张都清空时后台及社交链接显示默认图形；技能球仅绘制已设置图片的技能，名称仍保留在无障碍列表中。

技能和社交接口新增 `iconMediaId`、`darkIconMediaId`，响应新增 `icon`、`darkIcon` 媒体对象。`iconKey` 保留兼容旧客户端，新建后台记录自动使用 `custom`；这两个模块不再依赖本地图标注册表。分类图标仍沿用原方案。

34 个不同的本地图标文件已迁移为 34 个媒体对象：24 项技能的通用图标、6 项技能的深色版本，以及 3 个社交链接的两套图标，共 36 个关联（GitHub 的两套资源复用）。原始 76 个媒体加上图标后，媒体基线为 110。图标被技能或社交链接引用时，删除媒体返回 409。

新环境在完成基础内容导入后，于后端目录执行：

```powershell
Set-Location ..\vo1d-blog-api
pnpm prisma:generate
pnpm prisma:migrate:deploy
pnpm import:icons -- --source "..\vo1d-blog" --check
pnpm import:icons -- --source "..\vo1d-blog"
```

`import:icons` 只补充现有记录的空图标关联，不重建内容，不改名称、排序、可见性，也不替换自定义图标。可重复执行；不要以 `import:frontend` 代替图标迁移。

## 多账号怎样配置

在后端被忽略的 `.env` 使用 `STEAM_ACCOUNTS`。下面仅为结构示例，必须替换占位值；账号名称应便于区分：

```dotenv
STEAM_SYNC_ENABLED=true
STEAM_SYNC_INTERVAL_SECONDS=300
STEAM_ACCOUNTS='[{"name":"vo1d","steamId":"<17位账号标识>","apiKey":"<该账号密钥>"},{"name":"vo2d","steamId":"<17位账号标识>","apiKey":"<该账号密钥>"},{"name":"vo3d","steamId":"<17位账号标识>","apiKey":"<该账号密钥>"}]'
```

非空 `STEAM_ACCOUNTS` 优先于旧 `STEAM_ID` / `STEAM_API_KEY`；为空时兼容旧单账号配置。支持 1～10 个不同 SteamID64，重复账号会被拒绝。密钥仅存后端环境，不进入浏览器、接口响应或文档。

修改配置后，在后端目录执行 `docker compose --profile app up -d`；代码更新时加 `--build`。宿主机运行则重启 `pnpm start:dev`。

当前 vo1d、vo2d、vo3d 三个账号都已配置并真实同步成功。状态页分别显示账号游戏数、成功时间、错误和冷却状态。后续换密钥时修改对应账号配置，再重启后端。

## 同一游戏如何合计

- 博客游戏只关联一次 `steamAppId`。快照按“账号 + App ID”保存，游戏库和公共游戏响应按 App ID 合并。
- 相加所有可用账号的 `playtimeMinutes`，最后取 `floor(总分钟 / 60)` 作为 `playtimeHours`。1200 小时 + 200 小时 = 1400 小时；31 分钟 + 31 分钟 = 1 小时。
- `accountBreakdown` 返回各账号分钟数和快照状态，公共游戏响应不暴露 SteamID64。近两周分钟有未知值时总值保持空；最后游玩时间取最新，汇总同步时间取参与账号中最早的时间。
- 每个账号独立请求、冷却及重试。网络失败时保留其上次可见快照并标记 `stale`，其他账号继续更新。
- 私密、无权限或尚未成功同步的账号不参与公开汇总，并标记 `incomplete`。没有任何可用关联数据时回退手工时长。
- 从配置移除的账号不再参与汇总，旧快照保留。不同账号拥有同一游戏时，同名匹配先按 App ID 去重。
- 手工时长、个人评分、评论、喜爱等级、封面和顺序不被同步覆盖；Steam 新游戏也不会自动创建博客条目。

本次实际 Apex 快照：vo1d 72,987 分钟、vo2d 8,304 分钟、vo3d 1,053 分钟，总计 **82,344 分钟 = 1,372 小时 24 分钟**，博客显示 **1372h**。这是核对时的数值，会随同步更新；1400 小时是用户举的计算示例。

本次唯一同名关联新增 20 个，博客游戏总数仍是 47，已关联数从 12 增至 32。无法唯一同名匹配的项目可在编辑页手动选择。

## 博客接入与验证

博客已接入技能、社交链接、游戏，包括导航与页脚社交图标。后台修改这三个模块后，刷新博客即可读取。`VITE_API_BASE_URL` 默认 `http://localhost:3100`，部署时用博客 `.env.example` 配置真实地址并重新构建。

三个模块支持分页、加载、空数据、失败重试及取消请求；可见页面约每分钟刷新。成功空列表不会回退静态数组。书籍、照片、文章和站点文案现已接入，详见 [完整联动](full-integration.md)。原静态数组保留；已迁移图片和图标原件已移至桌面归档，详见 [原始资源归档](../../vo1d-blog/README.md#原始资源归档)。

技能球和游戏封面取色需要图片服务允许博客来源；本机 MinIO 已验证允许 `http://localhost:5173`。

本次验证：后端类型检查、静态检查、构建、125 项单元测试和 49 项隔离数据库测试；后台类型检查、静态检查、构建、31 项单元测试、12 项模拟浏览器测试和 2 项真实后台测试；博客类型检查、静态检查、构建及 Chrome 真实页面、空数据和重试检查。博客构建仍有较大文件分块提醒。

重跑博客只读验证：启动两个前端和后端，在后台目录执行 `node scripts/verify-blog-content.mjs`。结果位于本地 `docs/blog-content-verification.json`，截图位于 `docs/screenshots`；两者已由 `.gitignore` 排除，不随仓库发布。脚本不修改后端数据。

没有新增依赖。[Steam 官方接口](https://partner.steamgames.com/doc/webapi/IPlayerService)提供各账号时长，本项目负责汇总；本地图标转码沿用 [Sharp](https://sharp.pixelplumbing.com/api-constructor/)。
